CS 2420 — Sorting Algorithm Steppers

Interactive teaching tools · Data Structures & Algorithms · Weber State University

Nothing to install. Click any of the three below and it runs in this browser — no account, no download, no setup. Each one is a single self-contained page.

These were built to solve a specific classroom problem. A sorting algorithm is a process that unfolds over time, and a textbook can only show you single frozen frames of it. Each stepper walks one algorithm one step at a time, with its source code beside the data, so the code and what the code is doing are visible at the same moment.

O(n²) Sorts

Bubble, insertion and selection sort — the three that are easy to write and slow to run.

  • Loop bounds shown as live numbers, so j < n-1-i stops being abstract
  • A generated pass-by-pass table of the whole run
  • Why bubble sort's early exit is fragile, and what happens without it
  • A case where only one of the three preserves the order of equal values

O(n log n) Sorts

Merge, quick and heap sort. Each works on a structure a flat array cannot show, so the stepper draws it.

  • Merge sort's temporary halves, with all three cursors on them
  • Quick sort's pivot and the boundary the partition maintains
  • Heap sort as an actual binary tree, which is the one of the three that is genuinely unreadable as a row of numbers
  • Comparison counts verified against the real C++ implementation

Non-Comparison Sorts

Counting, bucket and radix sort — three algorithms that sort without ever comparing two elements to each other.

  • The count array, labelled with the value each counter stands for
  • Buckets drawn as rows showing the range each one covers
  • Radix sort's ten digit counters, and the output array filling from the right
  • Four inputs showing why the memory cost runs from 9 cells to 801

How to use one

  1. Take the tabs in order. The first three walk a single algorithm each; the last one compares all three.
  2. Next advances one step, or press Play and watch it run. ← and → also work.
  3. Click any line of code for a plain-language breakdown of that line — what it does, and the specific mistake it invites. The explanation stays pinned while you keep stepping.
  4. Switch the input buttons to see the same algorithm on sorted, reverse-sorted and duplicate-heavy data.

Each page carries a self-check that runs on load and reports at the top: it re-runs every algorithm on every input and verifies the results are correctly sorted, that each step highlights a real line of code, and that the comparison counts match the C++ the students actually write. A green bar means the demonstration you are watching is a correct one.
